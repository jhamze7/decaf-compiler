Overall, your code is well constructed and easy to read. We took a different approach when it came to 
checking for reserved words; while you made a new regex to match the text to a reserved word, 
I made a helper function is_reserved() to check if some text is in the set of reserved words. 
One issue with the regex, though, is that it does not have "^" at the beginning, or "\\b" at the end, 
like your keyword regex does; this could cause matching mid-token. Besides that issue, I believe both 
approaches are valid.

It was wise of you to free up your regexes in the cases that errors are thrown. Given the amount
of times you free up in the code, making a helper method to do this work and calling it in place 
of the large chunks of freeing code could have improved readability.

I like how you included an "invalid_hex" regex. This allows for robust error handling and clear error messages.
In my code, invalid hexlits fall down to the "Invalid token!" error, the same way an invalid declit would.
All in all, your code seems to do everything it's supposed to. Nice work!
